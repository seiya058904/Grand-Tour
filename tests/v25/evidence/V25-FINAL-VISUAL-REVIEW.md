## 响应式界面观察

### 320 与 390

两种窄屏都保留品牌、赛段名、暂停/赛况/快速完赛、画布、努力档位、Auto、补给和能量信息。已见区域内没有按钮叠压、整行被横向裁掉或重要计时/剩余距离被车手名牌遮挡。320 的场景仍显示主角名牌、跟轮目标、金色定位线、比赛时钟和海拔；390 留白略宽，三档努力操作的标题更松。

320 底部速度大数值与 `km/h` 小单位的间距偏紧，辅助单位和短说明需要更仔细地读。密集集团中大量车手轮廓相互覆盖，低分辨率下单个队服与车轮的辨识有限；主角名牌和定位线仍能提供定位。这是 P3 可读性/密度限制，没有看到影响开始、暂停、进攻或补给识别的阻断问题。

截图是有限视口，不能用底部截断判定页面元素溢出，也不能由此断言所有下方内容都可读。390 的移动 Race Centre 另有专门截图：标题、关闭按钮、冻结表格、两行主 tab、局势细分 tab、搜索、定位我、集团摘要和车手列表层级清楚。底部提示条接近屏幕下沿，下方车手行被滚动窗口截取属于可滚动列表的呈现；这张静图不能独立证明完整滚动范围或触摸操作成功。

### 768 与 1080p

768 中赛段标题和三项头部操作共存，五项数据区能保留其标签，主要按钮不碰撞。公路画面、名牌与能量条顺序清楚。

1920×1080 保持左侧比赛和右侧 Race Centre 双栏，右侧玩家行的金色强调与画布中的玩家名牌一致。主要数据和努力按钮可区分，画布边缘、道路和轮胎未见新增错位。画布下方的跟轮说明、快捷键、车队缩写和底部小数据字号仍小，属于既有信息密度限制。

### 4K 大屏 CSS

实际 4K 图中，比赛区域和右侧面板明显展开，画面宽度利用更合理，集团有更多横向空间。距离 HUD、三枚名牌、努力按钮与数据列均没有观察到遮挡。页面下部的集团板、GC 对手和赛段剖面保持连贯，没有被扩大后的画布压出可用区域。

对应 `ui.json` 记录 4K 画布 CSS 尺寸为 1902×538，1080p 为 1300×458；这是浏览器几何证据，并非凭截图估算。较早 V24 4K 图显示更窄的中央内容区，但该图中文字体存在方框、赛况也不同，不能拿它评价 V25 字体修复或做同局势像素质量比较。画布面积变化可从布局与记录核实。

4K 100% 仍有较多细小文字，尤其右栏次级行、键盘说明和底部路线附注。大屏布局并未把所有字号按分辨率等比例放大。在物理显示尺寸、系统缩放和用户视距未知的情况下，不能将截图中这些小字笼统宣告为不可读；应保留为 P3，并在真实高 DPI 设备上继续评估。本次没有看到关键按钮标题或主数值不可辨认。

## 三组自然播放帧观察

### 村落

V24 首帧画面内部靠中间树丛下有一座房屋；下一帧房屋直接不见，房屋仍处于视口内部，不能解释为从边缘移出。V25 同一开局已按固定地点选取房屋，右侧两座建筑在 0–6 帧保持形状和相对位置，随镜头逐步左移；没有整片村庄淡入淡出或大块建筑在画面内部突然增减。树与建筑具有不同于近景路缘的运动量，保留原有层次。

骑手集团的姿态变化可见，车轮、身体和道路位置在这些采样帧中没有突发分离。它们不能证明相邻每一帧的踩踏相位或 60 FPS 平滑度。

### 林线

V24 0/1 帧之间，画面中部的一棵较深色高树消失；其他山峰与较浅色树仍留在画面。V25 0–6 帧保留这棵树并随道路逐步移动，周围的深浅树列也没有在相邻样本中整体显隐。山峰、山脊、路缘与骑手位置衔接连续，当前坡度上的轮胎接地关系在所见帧中正常。

帧序列中赛事广播进入天空区，某些次要名牌减少；主角名牌和路面没有被广播遮住。这些是独立的 UI 演出变化，不是树线变化；未把它们误判为本次场景补丁的回归。

### 终点人群

V24 第 0 帧路侧没有这一组终点观众；第 1 帧相应路段同时出现成组观众。V25 的第 0 帧已有可见观众，后续帧按道路坐标向左移动。广告牌和护栏从右侧逐步进入；观众在广告牌后只露出头部/部分身体的遮挡顺序合理。没有看到观众整批在画面中央生成、在画布里漂浮，或出现在主骑行轨迹中。

冲刺按钮从准备状态变为明确的金色可用状态，功率/速度增加时骑手伏身变化可见；关门提醒位于天空上方，没有盖住主角车身或剩余距离。这 7 帧覆盖接近终点区域，最后一帧主角尚未冲线，因此不能用于评价冲线后成绩弹窗或领奖衔接。

## 静态设计扫描提示的处理

实际读取 `evidence/v25/design-detector.json`，共 92 条提示：84 warning、8 advisory；其中 64 条 `undersized-ui-text`、6 条 `tiny-text`。这些是扫描条目数，不代表 64 个已经在本次视口中逐一验证的不同缺陷。其他包含品牌强调线、字号层级、间距和阴影等规则提示。

本次看图支持“次级文案偏小、窄屏密度偏紧”的 P3 记录，没有找到关键不可读/遮挡的升级证据。不会把 92 条提示改写为 PASS，也没有依据扫描风格偏好重画成熟界面。未来改善应以具体屏幕、具体控件的读写任务为依据，并保留当前设计身份。

## 剩余限制与交付判断

- P3：320 速度单位、短说明与微文案密度；4K 100% 的次级文字偏小。当前可交付候选可带此限制继续打包。
- P3：窄屏大集团的单车/队服辨识度有限，当前定位依赖名牌和金色标识。
- 本次实际查看的是播放产生的全部 7 个采样静帧，并未观看 `.webm` 的每一帧；截图间隔约 400 ms 加截图开销。不能由此判断亚帧抖动、踩踏频率、掉帧、GC 停顿或全过程手感。
- 本轮没有独立看 TTT 编队全程、雨雪全程、冲线到最终领奖，也没有看 DPR2 截图或运行实体移动设备；相关独立证据由总审计记录。没有把脚本几何检查当作这些画面的人工验收。
- 初始 4K 图的字体方框和图片角落的 FPS 数字均不用于本轮前后性能结论；性能只认同条件的独占 ABBA 与 soak 报告。
